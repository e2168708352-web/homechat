# 自建端到端加密聊天系统：私人服务器搭建指南

一份完整的教程，教你把一套**消息端到端加密、数据只存在自己机器上、不依赖任何商业平台**的私人聊天系统架起来。

读完并照着做，你将拥有一个"自己的 WhatsApp / 微信私聊"，代价是**一台常开的机器**和大约一小时的搭建时间。

> 本仓库只包含这份搭建文档，不含任何可运行代码、不含任何密钥与账号信息。所有用到的组件都是开源软件，链接见文末。

## 1. 最终效果

- **私聊 / 群聊 / 图片 / 文件**都能发，体验接近主流 IM。
- **消息端到端加密**（OMEMO）：聊天内容在离开你的设备之前就加密了，服务器和网络中间人看到的只是密文，**包括你自己架的那台服务器也解不开**。
- **数据自托管**：账号、好友关系、消息记录、上传的文件，全部落在你自己的机器上，不会被任何平台拿去"分析"。
- **没有公网 IP 也能用**：通过 EasyTier 组网，异地的人也能连上你的服务器。

## 2. 架构与选型

整套系统由四层组成，每一层都只负责一件事：

```
┌─────────────────────────────────────────────────────────────┐
│  手机客户端  Conversations（安卓，开源）                        │
│      └─ OMEMO 端到端加密：明文只存在于两台通信的设备上           │
├─────────────────────────────────────────────────────────────┤
│  XMPP 服务器  Openfire（开源，Java）                          │
│      负责账号、好友关系、离线消息存储、文件上传中转               │
│      （它只看到密文，解不开内容）                               │
├─────────────────────────────────────────────────────────────┤
│  组网层  EasyTier（开源，P2P 虚拟局域网）                       │
│      给你和你的朋友各分配一个虚拟 IP，像在同一个内网里一样互通    │
│      没有公网 IP 时，靠公共中继服务器穿透 NAT                   │
├─────────────────────────────────────────────────────────────┤
│  物理机  一台常开的电脑 / 低功耗小主机 / VPS                     │
└─────────────────────────────────────────────────────────────┘
```

**为什么这样组合，而不是直接用某个成品 App？**

| 方案 | 问题 |
|---|---|
| 用 Signal / Telegram 等现成 App | 数据（至少元数据）经过别人的服务器，你无法掌控存储 |
| 只架一个 XMPP 服务器 | 没有公网 IP 或固定 IP 时，异地设备连不进来 |
| 只架一个 VPN | VPN 只解决"连通"，解决不了账号和聊天记录 |
| 加 EasyTier 组网层 | 无论服务器有没有公网 IP、无论 IP 是否漂移，虚拟 IP 都不变，客户端配置一次即可 |

这四层各司其职，缺一层都不完整。

## 3. 安全边界（请先读这一节）

这是全文最重要的一节。诚实地说明这套方案**能防什么、不能防什么**，避免你产生错误的"绝对安全"预期。

### 加密了什么

| 数据 | 状态 |
|---|---|
| 聊天内容（文本/图片/文件） | ✅ 端到端加密（OMEMO），服务器解不开 |
| 传输过程 | ✅ EasyTier 网络密钥加密 + TLS，双重加密 |
| 离线消息（对方不在线时发的内容） | ✅ 以密文形式存在服务器上，上线后才解 |

### 没有加密 / 无法加密的（元数据）

1. **公共中继知道"谁在跟谁通信"**：如果没有公网 IP，流量会经过公共中继服务器。中继看不到内容，但能看到**某个虚拟网络在某个时刻有流量、流量多大、两端大概在哪个网络**。这是本方案里你唯一"靠自己关不掉"的口子——除非自建中继（见[进阶](#11-进阶优化)）。
2. **服务器知道"谁加了谁、谁什么时候在线"**：好友关系和在线状态是 XMPP 协议的基础，服务器必须知道才能工作。这些元数据在你自己的机器上。
3. **上传的文件是明文落盘的**：文件经 OMEMO 加密的只是"下载链接"这条消息；文件本体由 EasyTier + TLS 保护传输，但最终以明文存在你自己的硬盘上。只要服务器不搬离你的机器，这符合"数据只在自己机器上"的目标。

### 一句话判断标准

> 你的目标是**"防数据被平台/网络中间人大肆收集"**——这套方案做到了。
> 如果你的威胁模型是**"防国家级对手或入侵你服务器的人"**——那还需要额外的加固（文件加密落盘、自建中继、服务器全盘加密），本指南只点到为止。

- **一台常开的机器当服务器**：可以是家里一台低功耗小主机 / 旧电脑 / NAS / 树莓派，也可以是便宜的 VPS（有公网 IP 的话甚至可以省掉 EasyTier）。

| XMPP 域名 | 建议直接用服务器虚拟 IP | `10.144.144.1` |

## 5. 第一步：组网（EasyTier）

EasyTier 是一个跨平台的 P2P 虚拟组网工具，相当于"没有中心服务器的 Tailscale"。所有设备用同一个 `network-name` 和 `network-secret` 加入后，就能用虚拟 IP 直接互访。

### 5.1 服务器端启动

下载对应平台的 `easytier-core` 后：

```bash
# 生成一个随机密钥（28 位左右），自己记好，别外传
openssl rand -base64 21

# 启动（Linux 示例，需 root 建 TUN 网卡）
easytier-core \
  --network-name my-family-net \
  --network-secret '<上面生成的随机密钥>' \
  -i 10.144.144.1
```

Windows 下用管理员权限运行同样命令即可；macOS / Android 用法见官方文档。

### 5.2 加入公共中继（没有公网 IP 时必须）

如果你的服务器没有公网 IP（绝大多数家庭宽带都是），别人在外面就找不到你。EasyTier 支持挂载**公共中继服务器**来做 NAT 穿透：

```bash
easytier-core \
  --network-name my-family-net \
  --network-secret '<密钥>' \
  -i 10.144.144.1 \
  -p tcp://<公共中继地址>:11010
```

- `-p` 可以写多个，写 3~5 条更稳（一条挂了自动换）。
- 公共中继地址可以从 EasyTier 社区、官方文档或社区列表里找。**注意：公共中继是志愿者提供的，可能停服，且能看到你的流量元数据。**
- 想要更私密 / 更稳定，就自己在 VPS 上跑一个中继：`easytier-core --relay`（见[进阶](#11-进阶优化)）。

### 5.3 验证组网通了

在任意一台已经加入的设备上：

```bash
easytier-cli peer
```

能看到其他设备（含服务器 `10.144.144.1`）就说明组网成功。

## 6. 第二步：安装 XMPP 服务器（Openfire）

Openfire 是开源的 XMPP 服务器，负责账号、好友关系、离线消息和文件上传。

### 6.1 安装

- **Linux**：下载官方 tar 包或 deb/rpm，解压后 `bin/openfire start`。
- **Windows**：下载安装包，双击安装为服务。
- 需要 Java（Openfire 5.x 需要 Java 17 及以上）。

### 6.2 首次配置向导

启动后，浏览器打开管理台：

```
http://127.0.0.1:9090
```

按向导设置：

1. **语言**：选你顺手的。
2. **服务器设置**：**XMPP 域名填服务器的虚拟 IP**（如 `10.144.144.1`），不要填 `localhost`，否则别的设备无法登录。
3. **数据库**：单机小规模选"内嵌数据库（Embedded）"即可，零配置。
4. **管理员**：设置管理员账号密码，这是你管理服务器的钥匙，务必记牢。
5. 完成后登录管理台。

### 6.3 让手机能发图片和文件（HTTP File Upload）

Openfire 自带的 HTTP 上传组件默认可能没启用，在管理台里：

- 进入 **插件 / 服务** 或 **系统属性**，启用 `httpfileupload`（HTTP File Upload）服务。
- 确认端口 `7070`（HTTP 绑定，供网页自测）可用：浏览器打开 `http://10.144.144.1:7070`，出现 "Openfire HTTP Binding Service" 字样即正常。

### 6.4 TLS 证书

Openfire 默认使用自签名证书，客户端第一次连接会提示"证书不受信任"。**这是正常的**，选择"信任/继续"即可——这个证书的作用是加密传输，不代表服务器身份被第三方认证。自己用，自签名完全够用。

## 7. 第三步：创建账号并互加好友

### 7.1 创建账号

在管理台 **用户/群组 → 创建用户**，给你自己和每一个家人朋友各建一个账号：

- 用户名：纯英文/数字，如 `me`、`mom`、`xiaoli`。
- 密码：每人一个，建议各不相同。
- 登录地址（JID）格式：`用户名@10.144.144.1`。

> 也可以在管理台开启"允许注册"，让朋友拿到网络密钥后自助注册。但自助注册意味着"拿到组网密钥的人都能注册"，请只在完全信任的小圈子里开。

### 7.2 互加好友

XMPP 的好友是双向订阅关系。最简单的方式是**客户端里互扫对方的二维码**（Conversations 支持），或者双方在通讯录里手动输入对方的完整 JID 添加。

> 加好友这一步不需要服务器参与审批——你们自己互相添加即可，服务器只是存着这条关系。

## 8. 第四步：开启端到端加密（OMEMO）

**OMEMO（XEP-0384）是这套方案的核心**：消息在发送端加密、接收端解密，服务器全程只能看到密文。

好消息：**Conversations 默认就强制使用 OMEMO**，你基本不需要手动开启。要做的只有一件事——**核对指纹**：

1. 在 Conversations 里点开某个对话 → 右上角菜单 → **安全 / 加密详情**。
2. 双方各自会看到一串**安全码 / 指纹**（如 `A1B2 C3D4 …`）。
3. **当面或通过另一条可信渠道（如打电话）逐字核对**这段指纹是否一致。
4. 一致就点"信任"。之后如果有人中间人攻击，指纹会变，你能立刻发现。

> 指纹核对是端到端加密**唯一**能防止中间人攻击的环节。跳过它，等于把"别人偷看"的门留了一条缝。

## 9. 第五步：手机端接入（Conversations）

Conversations 是安卓上最成熟的 XMPP 客户端，原生支持 OMEMO。

1. 安装 Conversations（官网 / F-Droid）。
2. 打开 → **我有账号** → **使用自己的提供者**（不要选官方推荐的公共服务器）。
3. 填写：
   - 地址：`me@10.144.144.1`
   - 密码：你在第 7 步设的密码
4. 弹"证书不受信任"时选**信任 / 继续**。
5. 登录成功后，通讯录里能看到已加的好友，点开即可加密聊天。

### 手机端的"后台保活"（重要）

手机系统为了省电，会杀掉后台的组网和聊天应用，导致收不到消息。务必给两个 App 放行：

- 设置 → 应用 → EasyTier / Conversations → **电池** → 选"不限制 / 允许后台活动"。
- 各品牌叫法不同：小米选"无限制"，华为把"应用启动管理"改"手动管理"并全开。

否则你会遇到"锁屏几分钟后就收不到消息"的怪现象。

## 10. 常见问题

**Q：手机提示"无法向对方发送加密消息" / 发送失败？**
对方可能还没上线发布过加密设备。**让对方先给你发一条消息**（登录后第一次发消息会自动发布密钥），之后你就能正常加密回发。

**Q：消息发出去是"未加密"的？**
说明对方这台设备还没有 OMEMO 密钥。第一次建立加密会话前，先让对方主动发一句，或用[第 8 节](#8-第四步开启端到端加密omemo)核对指纹。

**Q：换了热点 / 换了 Wi-Fi，会不会失联？**
不会。物理网络怎么变，虚拟 IP 不变，客户端里的服务器地址不用改。

**Q：服务器关机了，消息会丢吗？**
不会丢。对方发的消息会以密文存在服务器上，等你的服务器开机、客户端上线后补发。

**Q：为什么浏览器打开 7070 是英文白页？**
那是 Openfire 的 HTTP 绑定服务自测页，出现它正说明网络通了——这正是我们想要的。

## 11. 进阶优化

- **自建中继，彻底摆脱公共中继的元数据暴露**：在 VPS 上跑 `easytier-core --relay`，把它的地址写进所有设备的 `-p` 参数。
- **服务器直接有公网 IP / 固定 IP**：可以省掉 EasyTier，直接用 Openfire 的公网地址，客户端填域名即可；EasyTier 只在"无公网 IP"场景才必需。
- **文件加密落盘**：如果服务器将来要搬离你的机器，考虑给上传目录做透明加密（如 Linux 的 fscrypt / LUKS）。
- **多设备**：同一个账号可以在多台设备登录，OMEMO 会为每台设备分发独立密钥，互相都能解密。
- **异地自动重连**：用系统级守护（systemd / 计划任务）保证 EasyTier 和 Openfire 开机自启、掉线自动拉起。
